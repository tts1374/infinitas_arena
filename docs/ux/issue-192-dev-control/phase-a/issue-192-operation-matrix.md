## 1. 文言の方針

ボタンは「対象に対して何をするか」、状態は「今どうなっているか」を書く。正規の製品操作と、検証用プロセス・ファイルの操作を分ける。WS/store/generationなどは詳細ログの用語とし、主操作の名前に使わない。

| 旧案 | 改訂案 | 意味・補足 |
| --- | --- | --- |
| DEV CONTROL | 1人で動作確認 | この別窓の目的 |
| Host | 主催者 | 対戦・開催の進行役 |
| 模擬参加者 / MOCK 01 | テスト参加者 / 相手1 | 本人以外を操作する対象 |
| 実クライアント / 模擬WS | アプリ画面あり / 画面なし | 「入力元と確認できる範囲」を開いて経路を確認。画面なしは通信・受付を確認するもの |
| 実連携 | 普段の連携ソフトから読み取る | 本人の入力元。テスト結果の書込み不可 |
| 模擬リザルトを投入 | この人の結果を送る | 画面ありはsource別の隔離入力（ファイル/local WS）→監視・自動提出、画面なしは正規WS提出 |
| Ready | 準備完了にする / 準備を取り消す | 通常対戦のReadyを切り替える。ゲーム内の準備を保証する意味ではない |
| 共通候補から選曲 | この人の曲を選ぶ（通常）/ 主催者が曲を確定する（開催） | 通常は各人の選曲枠、開催は主催者だけ |
| 明示退出 | この部屋から退出する… | 一時切断とは別の正規退出。再入室条件は製品に従う |
| 一時切断 | 接続を切る（席は残す） | 再接続待ちを作る。開催の対象を勝手に除外しない |
| 再接続 | 同じ人としてつなぎ直す | 一時切断からの復帰。退出済みの再入室とは別 |
| 新しいセッション | 最初からやり直す… | 検証用の設定・名簿を作り直す。記録を保持 |
| 停止 | 動作確認を終了する… | 検証用プロセスと予約入力を止める。本人のIIDX・連携ソフトは停止しない |
| 未提出を締切 | 未提出の人を欠場にして締め切る… | 開催。締切までは未提出のまま |
| force advance | 未提出の人を時間切れにして進む… | 通常対戦。開催の欠場締切と同じ操作名にしない |
| ログ・画像を保存 | 操作記録と画面を保存 | 操作・送信・受付・エラー、状態、画像を保存 |

状態語も整理する。「起動中」は起動処理中と紛らわしいため通常時は「動作確認中」、接続前は「接続しています」、切断中は「接続が切れています」、送信と受付は「送信しました／受付を確認しました」と分ける。実通信のないwireframeでは全体に「操作イメージ・通信しません」と明示する。

## 6. 状態に関係する上書き条件（全モード共通）

状態表で可でも、次の条件を満たさなければ操作しない。2026-10-18の再設計では「表にある操作をすべて常時表示する」を廃止する。操作可否と表示優先度を分け、今の主要操作を原則1つ見せ、接続・進行調整・確認全体の操作は名前付きメニューから開く。以下の理由は今の主要操作、状態メッセージ、または開いたメニュー内で読めるようにする。

| 条件 | UIの扱い・理由 |
| --- | --- |
| このモードに存在しない操作 | 操作自体を非表示。例: 開催のReady、通常対戦の「主催者がこの曲を開始」 |
| この状態では使えない | 別の場面の操作は常時並べない。例: 開始前は「プレーが始まったら、結果を送れます」と表示し、入力・送信ボタンは出さない。いま必要な操作が条件不足なら、その操作または状態メッセージに理由を表示。例外メニューを開いたときの無効項目にも理由を表示 |
| 主催者以外を選択 | 主催者の現在の進行操作は画面上部に固定し、実行者を表示。締切・選曲取消・終了は「進行の調整」。選択中の相手の役割へ誤って送信しない |
| 自分Aを操作対象に選択 | 準備・選曲・テスト結果送信はアプリへ誘導。「自分はアプリで操作します」「普段の連携ソフトから読み取ります」。テスト結果の入力欄を出さない |
| 対象が切断中 | 送信・選曲・Ready・退出は無効、「接続が切れています」。再接続だけ有効。提出予約も取消 |
| 対象が退出済み | 接続復帰ボタンも無効、「退出済みです。再入室とは別の操作です」。対象IDを新参加者へ使い回さない |
| 開催の主催者が切断中 | 既に開始した曲の有効な結果提出、再接続、公開情報の閲覧を除き進行・退出などを止める。「主催者の再接続を待っています」。5分の絶対期限を延ばさない |
| 操作の返答待ち | 同じ対象の競合操作を無効、「前の操作の返答を待っています」。未応答を成功表示にしない |
| 提出済み・欠場確定済み | 結果フォームを状態表示へ置換し、二重送信しない。「この人の結果は受け付けられました」または「この曲は欠場で確定しました」 |
| 次曲待ち・当該曲対象外 | 結果フォームは出さず、「この人は次の曲から参加します」 |
| 曲・ROUND・世代・接続が切替 | 古い確認・予約を失効。直前の対象を現在曲へ自動転用しない。再接続後は最新snapshotと再照合 |
| 動作確認を停止済み | 閲覧・記録保存・最初からやり直す以外を無効。再開時に予約は復活させない |

## 8. wireframeへの反映・検証基準

確定したPhase AのUI正本は **補正後`issue-192-control-window-v3.html`＋本表**。v2以前は過去の比較案として保存する。v3はボタンを減らすための情報配置の再設計であり、操作可否の条件は維持する。表の理由・条件が試作に欠けていたら、試作の都合で権限・受付条件を緩めない。補正後の視覚案全体もユーザー合意済み。試作の合意を製品実装の受け入れ完了へ読み替えない。

| 操作群 | v3での入口・表示 |
| --- | --- |
| 現在の主催者進行 | 上部の進行欄にその場面の操作だけ。開催開始→曲確定→この曲の開始→次曲。過去・未来のボタンは出さない |
| 通常のReady・本人の選曲枠 | 選択した相手の詳細に、その場面で必要な操作だけ。全員Ready前の開始条件は状態文で示す |
| 結果入力・送信 | 対象者が現在曲へ提出できる場面で入力欄と送信を表示。前後は待機／受付状態に置換 |
| 自動・遅延・未提出の設定 | 対象者の「送信設定」で次の提出値と送り方を開く。提出済み等では「次の曲で使う値」と表示。「送り方：手動／毎曲自動／10秒後／送らずに待つ」を閉じた状態でも表示 |
| 切断・再接続・退出 | 対象者の「接続のテスト」。切断と退出を別操作で示し、無効理由をメニュー内に表示 |
| 選曲取消・未提出締切・開催終了 | 上部の「進行の調整」。主催者の操作と明示し、実行時は対象と影響を確認 |
| やり直し・終了・画面あり構成で再起動 | 「確認全体の操作」。対象者の操作と検証全体に影響する操作を混ぜない |
| 状態・操作記録・保存 | 参加者状態は本人Aを含め一覧、直近の操作は下部。入力元の補足で状態を置換しない。詳細記録は開いて見る。必要な観測をメニューに隠して見落とさせない |

メイン画面は既存の別窓を並べて使う。v3の視覚案は今回課題となった操作窓単体を詳しく描いている。機能やメイン画面を削除する提案ではない。

確認対象:
- 5モードそれぞれで全表示状態を切り替え、通常のReady・選曲枠、開催の主催者開始・締切・次曲の可否を確認する。
- 対象A/B、主催者A/B、接続中/切断中/退出済み、未提出/提出済み/次曲待ち、主催者切断を掛け合わせ、無効理由が読めることを確認する。
- 通常の曲別結果から次曲へは自動であり、開催では主催者操作であることを確認する。試作上部の場面切替を製品操作として扱わない。
- モードの切替は独立サンプルを再作成する。全FSM・timer・通信・ファイル・受理の実装検証を完了したとはみなさない。

## 9. 根拠・範囲

### 2026-10-18 レビュー補正の表示・入力契約

- 「提出・欠場確定」の分母はsnapshotの `current_playing_player_ids`、分子はその集合の提出/欠場確定statusから求める。在室人数や接続中人数は別。大会の固定Nを退出・不在・次曲待ちで縮めず、欠場を有効な提出と呼ばない。合同も開始済み曲の対象者を退出だけで除外しない。
- 独立試作では場面に応じた対象ID集合を保持するサンプルで示す。実装時はsnapshotが正本であり、この試作の配列や状態ジャンプを製品FSMとして移植しない。NOT_PRESENT/LEFT等の詳細理由、再入室や期限の全経路は未再現。
- 終了状態の案内を一時切断の回復案内より優先する。開催E5/E6では「つなぎ直せます」と表示せず、記録保存・新しい検証へ誘導する。通常N5の存続中の部屋へ接続操作を提供する既存方針は変更しない。
- 初版の実画面相手は、既存の主要source（`inf-notebook`、`reflux`、`daken_counter_v3`）をsource別に扱う案。前二者の隔離ファイルと、後者の隔離local WSを区別する。legacy sourceは既存legacy有効条件に従う。本人Aの普段の対応sourceは変更しない。
- 起動時にsource・隔離入力先・対応可否を表示し、入力方式を用意できない構成では起動を拒否する。Bで既存資産による実現性を確認し、初版で扱えないsourceが判明したら黙って直接送信へ代替せずAで範囲を再調整する。これは新しいparser/WSサービスの実装完了や方式の確約ではない。
