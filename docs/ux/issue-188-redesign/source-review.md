## 見直しと合意状況

毎曲の準備操作を廃止し、通話・配信等でHostが確認して開始する方式で合意済み。参加時に別の連続参加設定は設けない。参加資格はゲーム内準備完了の証明ではない。休憩・参加者切断時も席と対象を残し、Hostが待つか進めるか判断する方式で合意済み。未提出の締切で欠場・大会0pt。配点・復帰・提出秘匿は維持する。原稿の「合意済みの変更」で旧規範との差を追跡する。

| 提案 | 現状と理由 | 変更の性質・選択肢 |
| --- | --- | --- |
| 入口の目的を分離 | 通常公開ロビーの見出しの直下に開催操作が並ぶ | 情報設計。3案を比較し、専用ページで合意済み |
| サイドバーで意味を読める | 現状は似た履歴/Roomアイコンを区別するためhover等が必要 | 常時ラベル、開催中への戻り、履歴の行先を検討 |
| 開催状態と自分の状態を分ける | 進行中にも準備完了人数と自分の準備状態が残る | 開始待ちは参加対象、プレー中は提出、結果は確定を主表示にする。毎曲準備は合意に従い廃止 |
| 兼任Hostの責務を分けて置く | 自分の参加と全体進行を読み分ける必要がある | 自分の参加・提出カード、下部に全体の開始。自分の準備ボタンは廃止。独立した管理パネルを積まない |
| 主操作を絞る | 進行中の途中締切が強調され、通常完了の待機との優先関係が曖昧 | 通常は自動提出を待つ。途中締切は補助操作、無効化/終了/Kickは確認付き |
| 副操作の影響を明示 | 曲別結果の無効化は現コードでは確認なし。次曲選択後も前曲の無効化可というルールを示す場所が必要 | 直前結果の詳細に無効化導線を残す。確認に曲名と集計除外を示す |
| 入室入力を簡潔にする | Issueは参加コード、既存UIはRoom ID＋参加コード | まず維持案と招待情報貼り付け案を比較。コードだけで検索する仕組みは今回新規契約として確定しない |

## 進行画面に関するユーザー指摘の反映

「あまりにも業務に寄ってないか」「通常対戦のデザインがあるのにそれを生かさないのはもったいない」という指摘を設計条件として追加。
初回試作は説明パネルと進行段階の帯を増やし、通常対戦の暗色/cyanを参照するだけになっていた。初回の具体配置は未採用として保持する。
改訂では `RoomArena.tsx` と通常ARENAの実描画（待機/選曲/プレー/結果）を参照し、曲ヘッダー、難易度バッジ、太字・斜体の曲名、READY/提出のプレイヤーカード、下部アクションバー、右側の曲履歴・開催条件、順位カードを土台にする。
20人対応・Host進行・結果秘匿・無制限曲数は開催仕様に合わせて拡張する。通常対戦のカウントダウン、自動次曲移行、プレー中のスコア公開は持ち込まない。詳細な参照対応は `prototype-review.md`。

## 合意記録と留保事項

1. 入口: 専用ページで合意済み。サイドバーのラベル/密度は採用した試作を基準とする。
2. 作成と参加は開催ページの2入口から個別ページへ進む方式で全体案として合意済み。
3. 参加入力の合意: 現行のID＋コードの個別入力を維持。招待文貼り付けは改善候補として留保し、コード単独で検索する新しい受付方式は採用しない。全体案として合意済み。
4. 重要操作の確認: 大会開始（名簿/N固定）、選び直し（譜面取消・再共有）、スキップ、締切、無効化、終了、Kick、明示退出。合同の未準備除外確認は新合意により不要。残る確認量も採用した試作と対応表のとおり合意済み。
5. 主催者/参加者の情報量: 主催者は全員、参加者は自分中心＋全一覧導線。詳細位置は採用した試作を基準とする。
6. 休憩・開始前切断: 席と対象を保ち、通話で申告してHostが待つか進める方式で合意済み。開始後は既存の未提出締切を用い、大会の欠場は0pt。自動除外やHostによる個別欠場指定は追加しない。

既存PRの再利用可否はこの段階では未評価。モデル世代から判断せず、新設計確定後に責務・契約・検証証拠と照合する。
