## 確認する流れ

試作の上部はレビュー用の条件指定。アプリの操作ではない。「Hostの開始・自動提出を再現」は別端末のHost開始や連携ツールの提出、Host復帰などを再現する。実通信や実ファイル読み取りを行わない。Host自身の開始待ち画面では再現操作を無効にし、画面内の開始を使う。

| 見る立場 | クリックで確認する流れ |
| --- | --- |
| 専任Host | 開催入口→作成→待機室→開催開始→「曲を選ぶ」→候補選択→譜面確定→通話等で確認してプレー開始→提出を再現→曲別結果→次曲選曲→右側「開催の管理」で終了→最終結果→開催履歴 |
| 兼任Host | 作成時にプレー兼任→譜面確定→全体のプレー開始。自分の準備ボタンなしで進め、自分の参加・提出カードを確認 |
| 参加者 | 参加→サンプル招待入力→待機→上部の画面指定でHost進行を再現→Host開始待ち→開始を再現→プレー・自動提出→結果→次曲待ち。準備ボタン・主催操作が出ないことを確認 |
| 通常対戦との往復 | サイドバーの通常対戦へ→進行中の開催へ戻る。画面移動と退出を別操作で確認。通常対戦本体は参照用の配置表示 |

「開催タイプ」で合同/大会を比較する。「画面を見る」は任意の場面からレビューするための入口で、サンプル状態を作り直す。「20人・切断などの状態を見る」で例外場面を選ぶ。各状態は独立したサンプルであり、切替後も入力や提出状態が続くことを保証するものではない。

休憩・切断の確認: 「通話で休憩を申告」または「開始前に参加者切断」を選択→Hostのプレー開始→接続中・プレーした人の提出を再現→14/15人提出のまま待機→右側「開催の管理」の締切→未提出1人の欠場確認→曲別結果→次曲。席と大会N=15は保たれる。切断例では締切前にレビュー用の復帰再現→提出再現を行い、同曲の有効結果へ戻れる。
休憩申告は試作上部に想定として記載する。製品画面に自動の休憩状態や休憩ボタンを追加しない。切断の接続表示と、未提出の受付状態を区別する。

## 情報階層と役割差

| 場面 | 主情報と主操作 | 補助・詳細 | 配置の理由 |
| --- | --- | --- | --- |
| 専用入口 | 参加／待機室作成 | 招待制、合同/大会の違い、開催履歴 | 通常ロビーの操作と開催操作を分離。2つの目的を読んで選ぶ |
| 待機室 | 人数・開催条件、Hostは開催開始、参加者は開始待ち | 招待情報、連携設定、終了/退出 | 作成と開催開始を混同せず、未確定譜面の準備を求めない |
| 選曲 | 全員が遊べる候補、選択中の譜面、確定 | 参加者一覧、直前結果管理 | 曲名クリックと確定を分け、候補変更時に確認ダイアログを増やさない |
| 開始待ち | 曲ヘッダー→参加対象カード→下部のHost開始または待機表示 | 右側に開催条件、曲履歴、管理の詳細 | 自分のカードを先頭に。参加対象はゲーム内準備完了の保証ではない。20人一覧がHostの主操作を押し出さない |
| プレー | 譜面、自動提出の状態、提出/欠場確定人数 | 連携障害、スキップ、Hostの途中締切/無効化 | 未準備の説明をプレー中の主情報にしない。進行中はスコアを出さない |
| 曲別結果 | 順位カード、詳細表、下部にHostの次曲操作 | 全順位、ここまでの総合、曲の管理、開催終了 | 通常対戦の結果表現を生かす。参加者の表は上位3＋自分の前後2から閲覧 |
| 最終結果 | 終了理由、大会総合／合同振り返り | 曲別結果、開催履歴、受信・保存状態 | 終了を次曲待ちと区別。0確定曲に優勝者を出さない |
| 履歴 | この端末の完全/部分記録と詳細 | 無効曲、最終受信時刻、未対応履歴 | 後日の同期や通常成績への合算を約束しない |

専任Hostは自分の参加・提出カードなし。兼任Hostは自分のカードと全体開始を分ける。兼任Host・参加者とも毎曲準備操作なし。参加者には主催操作を出さない。開催状態は曲ヘッダー、自分の状態はプレイヤーカードと提出の短い案内。色と状態名を併記する。
デスクトップでは中央に曲・プレイヤー・下部操作、右に曲履歴/開催条件/管理。狭い画面ではカードを2列にし、右側の情報を下へ積む。結果は順位カード＋詳細表。

## 合意した確認操作

| 操作 | 提案する確認 | 理由 |
| --- | --- | --- |
| 大会の開催開始 | 開始人数Nと新規参加締切 | 名簿・配点を固定するため |
| 合同の開催開始 | 追加ダイアログなし | 待機室作成とは別の明示操作であり、固定Nがない |
| 曲の開始 | 追加ダイアログなし | Hostが通話等で確認して開始。休憩/参加者切断でも対象は残し、Hostが待つか進めるか判断する |
| 選び直し | 確定譜面の取消と再共有を確認 | 参加者がゲーム内で選曲している可能性がある |
| スキップ | 自分の欠場・大会0pt | 提出の代替ではないことを明示 |
| 未提出の締切 | 欠場になる人数と以降受付不可 | 未提出と欠場を混同しない |
| 曲の無効化 | 対象曲名・全員の集計除外・履歴保持 | 次曲選曲/準備中も前曲の操作対象を読み違えない |
| 開催終了/Host退出 | 全員の開催終了・進行中曲の無効 | ページ移動とは別で、他参加者にも影響する |
| 参加者退出 | 同曲復帰と異なる次曲復帰条件 | 一時切断と明示退出を区別 |
| Kick | 対象名・再参加不可 | 対象の取り違えを防ぐ |

主操作は通常対戦に沿ったcyanの大きいボタン。補助操作はグレー。無効化/締切/終了は右側の開催管理、Kickはプレイヤーカードの管理から入り、実行直前に影響を確認。色・ラベル/幅は採用した試作を基準に微調整する。

## 引き継いだ規則と再設計の関係

配点、固定N、同点、欠場、上限人数、確定後入室による参加待ち、復帰、Host切断5分、結果公開、sourceの最初の有効提出、無効化可能な時期、履歴互換は維持する。入口と配置に加え、毎曲の準備操作・準備による曲開始条件を合意に従い変更する。
譜面確定後の途中参加と明示退出後の復帰待ちは理由を区別する。合同の開始時未準備による対象外扱いは廃止。Host切断時は提出を続けられ、スキップ・結果確定・進行操作が止まる。期限表示は試作用の固定例で実時計ではない。休憩/参加者切断は対象を保って進行可能。未提出のまま締め切った場合だけ欠場・大会0ptになる。
共通譜面や自動提出の受理、20端末間同期、保存成功、server/client互換は画面上のサンプルであり、製品の検証結果ではない。

2. 専用入口から作成・参加の個別ページへ進む構成、サイドバーのラベル/密度を採用。
3. 参加入力の合意: 現在のID＋コードを維持。招待文貼り付けで2項目を埋める案は改善候補として留保し、今回は必須仕様にしない。コード単独で検索する新しい受付方式は採用しない。
4. 上記の確認ダイアログの量と管理操作の配置を採用。
5. 各例外画面の説明と参加者結果の初期表示量を含む全体案を採用。
6. 休憩・開始前切断時も席と参加対象を保ち、Hostが待つか開始するか判断する方式で合意済み。開始後は既存の未提出締切を使い、欠場・大会0ptとする。自動除外やHostによる個別欠場指定を追加しない。

追記: Hostとの通話・配信で選曲/開始を共有し、運営と連絡が取れる前提はユーザー合意済み。音声通知を必須にするかという論点は解消し、アプリ音声は補助候補とする。
